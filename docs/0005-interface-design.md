# 0005 — 界面设计方向

状态：已选定并实施
范围：浏览器客户端（`internal/webassets`）的信息架构、视觉语言、交互规范、令牌系统

---

## 1. 目标与约束

这个产品的技术底座决定了它该长什么样，而这一点必须显式写下来，否则界面会退化成"又一个网盘"：

| 底座事实 | 对界面的要求 |
|---|---|
| 哈希链审计、可追溯的每次读写 | 历史与权限必须**内联可见**，不能藏在弹窗里 |
| 分享可限密码/次数/时效、可限定收件人 | 分享状态要成为对象的一等属性，而非一次性动作 |
| 服务端版本历史、内容寻址去重 | 版本是常态而非高级功能 |
| 单实例可服务 2000 人或 40 TiB | 密度与规模必须能撑住，不能只对 20 个文件好看 |
| 自托管、无第三方 CDN | 零外部资源、零构建步骤 |
| 管理员**看得到元数据但看不到内容** | 界面不能让权限看起来比实际更强 |

约束：
- 无依赖、无打包器；三份静态资源内嵌进二进制
- 内联渲染有严格类型白名单 + 内容嗅探 + CSP sandbox（见 `0004`）
- 用户数据只经 `textContent` 进 DOM

## 2. 方向探索

探索了四个差异明显的方向。评分 1–5，成本分越低越贵。

### A. Workbench（工作台）

键盘优先、命令面板为主动词。信息密度极高（28px 行高），几乎无边框，靠严格对齐建立秩序；等宽字体承担层级。

- 优点：生产力强，个性鲜明，实现成本低
- 缺点：对普通用户有门槛；触屏几乎不可用；不做响应式会直接崩
- 评估：易用 3 / 密度 5 / 无障碍 4 / 成本 2 / 个性 5

### B. Gallery（画廊）

内容即界面。缩略图占满视口，chrome 在交互时淡出；不提供列表。

- 优点：图片与媒体体验极佳，视觉冲击强
- 缺点：文本、代码、配置文件表现差；大量相似文件名难以扫描；密度低
- 评估：易用 4 / 密度 2 / 无障碍 4 / 成本 2 / 个性 4

### C. Canvas（自由画布）

文件可自由摆位，用空间位置帮助记忆，类似白板。

- 优点：空间记忆有认知依据，个性最强
- 缺点：位置对屏幕阅读器无意义（违背无障碍底线）；不可预测（违背原则 4）；实现成本极高；4 万个文件无法摆
- 评估：易用 2 / 密度 2 / 无障碍 1 / 成本 5 / 个性 5

### D. Atlas（自适应工作区）

**内容驱动视图，权限与历史内联可见，列数随宽度与选中态变化。**

- 优点：同时服务普通用户（默认清晰）与重度用户（密集、键盘、命令面板）；无瓶颈；差异化来自"信任可见"，而非视觉装饰
- 缺点：不如 B 惊艳，不如 A 极简；**必须真做自适应逻辑，否则会退化成固定三列**
- 评估：易用 5 / 密度 4 / 无障碍 5 / 成本 3 / 个性 4

### 评分汇总

| 方向 | 易用 | 密度 | 无障碍 | 成本 | 个性 | 结论 |
|---|---|---|---|---|---|---|
| A Workbench | 3 | 5 | 4 | 2 | 5 | 作为 Atlas 的键盘/命令层吸收 |
| B Gallery | 4 | 2 | 4 | 2 | 4 | 作为 Atlas 的一种**视图**吸收 |
| C Canvas | 2 | 2 | 1 | 5 | 5 | 否决：违背无障碍与可预测性 |
| **D Atlas** | **5** | **4** | **5** | **3** | **4** | **选定** |

**为什么是 D**：这个产品的差异化不在于"看起来酷"，而在于它敢让人看见真相——谁在什么时候拿了什么、这个文件被谁的链接指向、上一版是什么。Drive 和 Dropbox 把权限与历史藏起来，因为它们的模型里这些是次要的。这里它们是主体。界面如果不在视觉上表达这一点，就等于放弃产品主张。

A 的键盘与命令层、B 的媒体视图都被吸收为 Atlas 的组成部分，而不是并列方案。

## 3. 选定方向：Atlas

一句话：**一个安静、精确的工作区，文件是主体，系统的信任保证始终在场但不喧哗。**

三个支撑它的决定性设计：

### 3.1 自适应列数，而非固定三列

| 宽度 | 列数 | 导航 | 详情面板 |
|---|---|---|---|
| < 640px | 1 | 抽屉（顶部） | 全屏 sheet |
| 640–1024px | 2（图标栏 + 内容） | 图标栏 | 覆盖面板 |
| 1024–1440px | 2（图标栏 + 内容） | 图标栏（可展开） | 侧栏，仅选中时出现 |
| > 1440px | 3 | 图标栏（可展开） | 侧栏，选中时出现，可钉住 |

关键：**未选中任何对象时，详情面板不占位**。这是与固定三列的根本区别——它只在有对象时存在。

### 3.2 内容驱动的视图建议

系统按目录内容建议视图，并**说明理由**，用户可钉住：

| 目录特征 | 建议 | 理由 chip |
|---|---|---|
| ≥ 60% 且 ≥ 6 个可预览图片 | 画廊 | `Gallery · 12 images` |
| > 200 项 | 紧凑列表 | `Compact · 431 items` |
| ≥ 60% 文本/代码 | 列表（含摘要） | `List · mostly text` |
| 其余 | 列表 | `List` |

用户钉住后不再自动切换。这是在"内容优先"和"用户控制"之间唯一诚实的处理方式。

### 3.3 来源与权限内联

每一行在不动手的情况下传达：是否被分享（几个链接）、是否有历史版本、最近是否变动。

- `⇢3` 分享中，3 个链接
- `⟲` 有历史版本
- 无标记 = 私有、无历史

这是审计能力的界面表达，也是与竞品最实质的差别。

## 4. 信息架构

```
Atlas
├── 文件（主视图）
│   ├── 文件夹层级（树不变，视图可变）
│   ├── 视图：列表 / 紧凑 / 画廊
│   └── 详情面板（按需）
│       ├── 预览
│       ├── 属性
│       ├── 版本历史 → 恢复
│       ├── 关联分享 → 吊销
│       └── 对象活动（最近 5 条）
├── 分享
├── 回收站
├── 活动（审计时间线）
└── 访问（App Password / WebDAV）
```

原则：**导航不因视图切换而变化**。画廊和列表是同一层级树的两个投影，不是两个功能。

## 5. 布局规范

### 5.1 桌面（≥ 1440px）

```
┌──────┬────────────────────────────────────────────┬───────────────┐
│ rail │ head: 路径 · 搜索 · 密度 · 视图 · 主题      │  详情（按需）  │
│ 56px │────────────────────────────────────────────│   320px       │
│ 可展 │ 内容：列表 / 紧凑 / 画廊                    │  预览         │
│ 216px│                                            │  属性         │
│      │                                            │  版本  ⟲      │
│      │                                            │  分享  ⇢3     │
│      │ 状态条：存储 · 上传 · 在线                  │  活动         │
└──────┴────────────────────────────────────────────┴───────────────┘
```

- 头部单行，高 52px：面包屑、搜索、密度、视图、主题、命令面板
- 状态条高 28px，仅在有内容时显示（存储、上传进度、离线）
- 内容区可滚动，表头 sticky

### 5.2 平板（640–1024px）

- 2 列：图标栏（56px）+ 内容
- 详情面板为覆盖层，宽 `min(360px, 88vw)`，带遮罩
- 头部折行：面包屑一行，控件一行

### 5.3 手机（< 640px）

- 1 列
- 导航为顶部横条（图标 + 短标签）
- 详情为全屏 sheet，从底部推入，可下滑关闭
- 行高 48px（满足 44px 触控目标）
- 隐藏"种类""修改时间"列，保留名称 + 大小

### 5.4 RTL

全部使用逻辑属性（`padding-inline`、`border-inline-start`、`inset-inline-end`）。镜像时不写一套新样式，只翻转方向。图标方向性元素（返回箭头）用 `transform: scaleX(-1)` 在 `[dir="rtl"]` 下翻转。

## 6. 核心交互规范

| 交互 | 规范 |
|---|---|
| 单击行 | 选中，且立即填充详情面板 |
| 双击 / Enter | 打开（文件夹进入，文件预览/下载） |
| Shift + 单击 | 按**可视顺序**扩展选区 |
| ⌘/Ctrl + 单击 | 切换单项 |
| ⌘/Ctrl + A | 全选可视项 |
| Esc | 第一级：清除选区；第二级：关闭覆盖层 |
| ↑ ↓ / Home / End | 移动选区（roving tabindex） |
| PageUp / PageDown | 翻页 |
| Backspace | 上一层目录 |
| F2 | 重命名 |
| Delete | 删除（确认，进回收站，可撤销） |
| 空格 | 预览 |
| ⌘/Ctrl + K | 命令面板 |
| / | 聚焦搜索 |

**可逆性**：删除进回收站，提示条提供"撤销"。吊销分享需确认（不可逆）。恢复版本需确认（覆盖当前）。

**状态透明**：所有操作产生 3 类反馈之一——
1. 乐观更新（重命名、选中）
2. 进度（上传，逐文件）
3. 结果提示（toast，可含操作链接）

**无拖拽专属功能**：拖拽上传是加速方式，不是唯一路径；键盘与按钮必须能做同样的事（WCAG 2.5.7）。

```

--radius-sm: 2px   --radius: 4px   --radius-lg: 8px
```

### 7.4 字体与字号

| 角色 | 字号 / 行高 | 字族 |
|---|---|---|
| 标题 | 15 / 1.3 | UI 无衬线，650 |
| 正文 | 13 / 1.45 | UI 无衬线，400 |
| 元数据 | 11.5 / 1.35 | **等宽** |
| 微标签 | 10 / 1.2，字距 .09em，大写 | UI 无衬线，600 |

**所有元数据用等宽**（大小、日期、计数、哈希、路径）。这一个决定同时带来精确感与对齐，且不依赖任何装饰。

### 7.5 动效

```
--motion-fast: 120ms
--motion-base: 160ms
--ease: cubic-bezier(0.16, 1, 0.3, 1)
```

只动 `transform` 与 `opacity`。`prefers-reduced-motion: reduce` 下全部降为 0ms，仅保留状态变化。

### 7.6 密度

- `comfortable`：行高 36px，内边距 12px
- `compact`：行高 28px，内边距 8px

持久化到 localStorage。

## 9. 关键流程

### 9.1 搜索

1. `/` 或点击 → 聚焦搜索框
2. 输入即过滤当前目录（本地，即时）
3. 空结果 → 空状态说明"只搜索当前文件夹"，并提供"在全部文件中搜索"
4. Esc → 清空并还原

未来扩展：跨目录搜索走服务端，界面预留切换入口，不假装已支持。

### 9.2 预览

1. 单击 → 详情面板显示预览井（图片缩略图 / 文本前 9 行 / 类型图标）
2. 双击、空格或"打开" → 预览弹层
3. 弹层内：Esc 关闭，← → 在同目录可预览文件间切换
4. 不支持内联的类型 → 说明原因并提供下载（不显示"损坏"）

### 9.3 上传

1. 按钮、拖拽、粘贴三种入口，均到当前目录
2. 拖拽时浮层显示目标目录名
3. 队列串行，逐文件进度与失败原因
4. 单文件失败不丢弃其余；失败项提供"重试"
5. 完成后摘要：`上传 7 个，1 个失败`

### 9.4 分享

1. 选中对象 → 详情面板"分享"或右键
2. 选择类型（链接 / 投递箱）、密码、时效、次数上限
3. 创建后**一次性**展示 URL 并复制（token 只存哈希，无法再取回——界面必须明说）
4. 详情面板列出该对象的全部链接，可吊销；**不提供"复制原链接"**，并解释原因

### 9.5 批量操作

1. Shift/⌘ 多选 → 底部浮出选区条
2. 显示 `已选 12 项`、总大小、可用动作
3. 批量删除：一次确认，逐项执行，逐项报告失败
4. 部分失败 → 汇总 + "查看失败项"
5. Esc 清除选区

## 10. 状态设计

| 状态 | 表现 |
|---|---|
| **空目录** | 图标 + "这个文件夹是空的" + 上传/新建主操作 |
| **搜索无结果** | "没有匹配项" + 清除筛选 |
| **加载** | 骨架行（与最终行同高，避免跳动），>400ms 才显示 |
| **错误** | 说明 + 重试按钮 + 错误码（不暴露内部路径） |
| **无权限** | 说明"你没有访问此对象的权限"，**不暗示其是否存在**（与后端的 404 策略一致） |
| **离线** | 顶部 banner + 操作按钮降级为禁用并给出原因 |
| **配额已满** | banner + 上传禁用，链接到用量 |
| **部分失败** | toast 汇总 + 可展开详情 |

## 11. 国际化与无障碍

### 11.1 国际化

- 所有字符串来自键表，**不做字符串拼接**（词序因语言而异，接不上）
- 复数用 `Intl.PluralRules`；数字、日期、相对时间用 `Intl.*`
- 语言检测：`navigator.languages` → 回退 `en`；用户可覆盖，存 localStorage
- 已内置：`en`、`zh-Hans`
- 布局用逻辑属性，`dir` 可整体切换
- 日期不硬编码格式；不假设 12/24 小时制；不假设周首日

### 11.2 无障碍（WCAG 2.2 AA）

| 准则 | 措施 |
|---|---|
| 1.4.3 对比度 | 正文 ≥ 4.5:1，全部令牌验证 |
| 1.4.11 非文本对比 | UI 边界与状态 ≥ 3:1 |
| 2.1.1 键盘 | 全部功能可键盘完成 |
| 2.4.7 焦点可见 | 2px 焦点环，永不被裁切 |
| 2.4.11 焦点不被遮挡 | 焦点元素自动滚动入视口 |
| 2.5.7 拖拽替代 | 上传有按钮入口，不依赖拖拽 |
| 2.5.8 目标尺寸 | 24×24 最小，触屏 44×44 |
| 3.2.6 一致的帮助 | 帮助入口位置固定 |
| 4.1.2 名称角色值 | 图标按钮必须有 `aria-label`；列表用 `role="listbox"`/`option` |
| 4.1.3 状态消息 | 操作结果经 `aria-live="polite"` 播报 |
| 1.3.1 信息与关系 | 属性用 `<dl>`；表头用 `<th scope>` |
| 2.3.3 动画 | 尊重 `prefers-reduced-motion` |
| 1.4.13 悬停内容 | 悬停出现的内容也可聚焦触发 |

补充：`prefers-contrast: more` 自动切高对比主题；`prefers-reduced-transparency` 下取消遮罩透明度。

## 12. 可用性测试与验收标准

### 12.1 测试计划

5–8 名参与者（3 名轻度技术用户、3 名开发者/运维、2 名键盘或辅助技术用户）。任务：

1. 找出上个月谁下载过你的文件（用活动页）
2. 把一个 800MB 的文件夹分享给外部顾问，限 3 天下载
3. 找回一份被覆盖的旧版本
4. 在 300 个文件中找到某个合同并只读预览
5. 只用键盘完成：进入子目录 → 预览 → 返回
6. 在手机上传一张照片并复制链接

记录：任务完成率、时间、错误数、求助次数、SUS 分数。

### 12.2 验收标准（可测）

| 项 | 标准 |

### 实施中发现的三个问题

**CSP 静默禁用了一切内联样式。** 样式表是 `style-src 'self'`，不含 `'unsafe-inline'`。
后果是 `style="..."` 属性会留在 DOM 里但永不生效——包括 `#body` 的 flex 布局、上传进度条
宽度、若干表格对齐。表现是"布局莫名其妙不撑满"，而检查 DOM 时属性明明存在。这解释了为什么
状态条一直贴不到底部。

处理方式不是放宽 CSP（内联样式是 CSS 数据外泄的通道，这条策略是有意的），而是把所有 20 处内联
样式改为语义类，并把进度条换成原生 `<progress>`——它的 `value` 属性天然驱动渲染，不需要任何
样式注入。同时从 `el()` 里删掉 `style` 选项，避免下一个人再踩。

改为语义类之后的一个额外收益：样式集中在样式表里，RTL 与高对比主题只需要覆盖类，不必逐个
元素判断。

**焦点丢失让方向键失效。** 列表用 `role="listbox"` + `aria-activedescendant`，行本身不是
Tab 停留点。但渲染会重建 DOM，点击行之后焦点落回 `<body>`，方向键就无处可去。修法是在渲染
前记下"需要恢复焦点"，渲染后把焦点放回新的 listbox。这个缺陷是浏览器里的交互断言抓到的，
静态截图看不出来。

**来源标记需要后端支持。** 设计要求每行显示"是否被分享、是否有历史版本"。按行调用
`SharesForNode` 与 `Versions` 是一个目录 500 次往返。改为 `MarkersFor` 批量接口（两次聚合
查询），实现于两种后端；服务端按可选接口探测，后端答不了就只是少一个装饰，不影响列表。

未实施（与后端能力对应，不在本次设计范围）：

- 跨目录全文搜索（后端无索引）
- 离线写入队列（需本地持久层）
- 跨对象的多选分享（后端按单对象建模）
- `ja` / `ar` / `he` 语言包（`dir` 与逻辑属性已就绪，缺翻译）
